Why zero forwardRef is the real headline

forwardRef is how a NestJS codebase survives a circular dependency rather than fixes one. Not a single occurrence exists in src/, and neither does ModuleRef or LazyModuleLoader — the other two ways to reach a provider without declaring you depend on it. Nothing here is papering over a cycle; there is no cycle to paper over.

03 How the cycles were avoided

A graph this size does not stay acyclic by luck. Three registries sit at L0 and invert what would otherwise be back-edges from infrastructure into features — the classic source of NestJS cycles. Each is a single instance that feature modules write into at bootstrap, so the dependency points one way only.

Registry Owner Cycle it prevents
EntityAccessRegistry SharedModule Comments and attachments are polymorphic across projects, tasks, knowledge, contacts and invoices. Resolving readability directly would make SharedModule import every feature module that imports it. Modules register a check instead; an unregistered entity type is denied, not allowed.
RetentionPurgeRegistry RetentionRegistryModule The retention sweep must reach into every feature's tables. Features register purge handlers rather than the scheduler importing them. Deliberately not @Global() — three importers, all named, so the seam stays visible.
IndexRegistry SearchServiceModule Search indexing needs per-collection schemas owned by feature modules. Bootstrap providers (KnowledgeCollectionBootstrap, ProjectCollectionBootstrap, DocumentsCollectionBootstrap) register from the feature side.

MastraRepositoriesModule is a fourth instance of the same discipline: the @mastra/nestjs dynamic module resolves its factory's inject tokens only against its own imports, not the host module's providers, so the five Drizzle repositories were split into a module both sides can import.

06 Findings

Act on this

CI enforces types only — the DI check never runs

.github/workflows/typecheck.yml is the single workflow, and it runs pnpm typecheck. The verify script chains typecheck, lint, 127 unit specs and check:graph, but nothing invokes it on push or PR.

This matters specifically because of what check:graph exists to catch. Its own header records the incident: SystemModule kept exporting SystemAuditService after that provider moved to SystemAuditModule, and the first sign was nest start dying with UnknownExportException. tsc cannot see that — DI wiring is decorator metadata, not types — and the unit suite constructs services with new Service(mockA, mockB), so it never exercises the container either. The tool that closes the hole is written and passing; it just isn't gated.

Fix is one line — run: pnpm verify in place of pnpm typecheck, or a separate step. check:graph needs no Postgres, Redis, MinIO or Meilisearch: preview mode instantiates no providers and opens no sockets.

Dead edge

SystemModule imports EmailModule and never uses it

EmailModule exports MailerService and InboxService. Neither is injected anywhere under src/features/system/, and no injection edge crosses that module pair in the container graph.

The import reads as necessary because smtp-config.service.ts and imap-config.service.ts do reach into infrastructure/email/ — but for verifySmtp and verifyImap, which are plain exported functions, not providers. A direct file import, not a DI dependency. Removing EmailModule from system.module.ts:imports drops SystemModule from fan-in on EmailModule (5 → 4) and changes nothing at runtime.

Redundant, harmless

Seven modules import QueueModule even though it is global

QueueModule is @Global() and re-exports BullModule, so BullModule.registerQueue() already resolves the root configuration without the explicit import. Auth, DocumentIngest, FileProcessor, Mailbox, Mastra, Notifications, SearchService and System all list it anyway — it contributes zero injection edges.

Worth leaving alone. The pairing of QueueModule with BullModule.registerQueue() documents that the module owns a queue, and that intent is more valuable than eight removed lines.

Confirmed healthy

No request-scoped providers in first-party code

Every provider in src/ is a singleton. The nine non-default-scope providers in the graph are all third-party — Terminus health indicators, Pino's PinoLogger, and Nest's INQUIRER.

This is worth stating because request scope is contagious: one Scope.REQUEST provider bubbles up through everything that injects it, forcing per-request instantiation of whole subtrees. Nothing in this codebase starts that chain.

Confirmed healthy

Every declared export is owned or legitimately re-exported

Preview mode validates exports across the whole graph, and it passes. Three modules re-export whole modules rather than providers — SystemModule re-exports SystemAuditModule and SystemSettingsModule, AuthModule re-exports TokenRevocationModule, QueueModule re-exports BullModule. All resolve.

08 Reproducing this

The first command is already in package.json. The second needs no install beyond npx. 

# DI container assembles — no cycles, all exports valid, all deps wired.
# Instantiates nothing, opens no sockets: needs no Postgres/Redis/MinIO/Meili.
pnpm check:graph

# File-level import cycles across src/, type-only imports included.
npx madge --circular --extensions ts --ts-config tsconfig.json src

The declared-module SCC pass and the injection-edge counts in sections 02 and 04 came from Nest's own SerializedGraph, dumped by creating the app with { preview: true, snapshot: true } and reading app.get(SerializedGraph).toJSON(). That is the container's own record of what it wired, so it cannot drift from runtime the way a static parse can.

One caveat on reading that graph raw: its module-to-module edges include a synthetic link from every module to every @Global() module. Run a naive SCC over them and you get one large false cycle spanning Config, Cache, Database, Bull, Logger and the rest — self-loops like ConfigModule → ConfigModule are the tell, since no module can import itself. The cycle result above is computed over declared imports: metadata instead, which is the graph an engineer actually edits.
